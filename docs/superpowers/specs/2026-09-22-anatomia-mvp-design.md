# Анатомия — дизайн первой версии (MVP)

Дата: 2026-09-22. Статус: утверждён пользователем в чате, ожидает ревью текста.

## 1. Зачем

Русскоязычное веб-приложение для студентов медвузов, чтобы учить нормальную анатомию:
3D-атлас всего тела, 3D-тесты, карточки латынь↔русский, прогресс по темам.
Первый пользователь — жена автора, студентка 1 курса. Дальше продукт продаётся студентам и медикам.

Исследование конкурентов (Anatomy Learning, Easy Anatomy 3D, Учи Мед) показало дыру на рынке:
нет русскоязычного продукта, который одновременно работает в браузере на ноутбуке,
покрывает всё тело в 3D, показывает латынь и русский рядом и стоит по-студенчески.
Главные жалобы на конкурентов: цена (499–1000 ₽/мес), только мобильные версии,
у Учи Мед 3D покрывает мало систем, у Easy Anatomy вылеты и 1.1 ГБ на телефоне.

## 2. Рамки первой версии

Входит:
- 3D-атлас всего тела (2234 структуры BodyParts3D) с включением систем слоями.
- Все 2234 структуры модели BodyParts3D — с латынью и русским; темы организованы по
  разделам анатомии (остеология, артрология, миология — программа 1 курса; ангиология,
  неврология, спланхнология, органы чувств — программа 2 курса).
- 3D-тесты двух видов: «найди структуру» и «назови структуру», по темам.
- Карточки латынь↔русский с интервальным повторением.
- Экран прогресса: освоение по темам, серия дней.
- Работает в браузере на ноутбуке и телефоне, без регистрации. Прогресс в localStorage.

Не входит (осознанно, добавляется позже поверх той же архитектуры):
аккаунты, оплата, мобильные приложения, гистология/физиология/биохимия, видео,
AI-тьютор, женская модель, срезы для радиологии, офлайн-режим.

## 3. Источник 3D-данных и лицензия

- BodyParts3D 4.0, © Database Center for Life Science, лицензия CC BY 4.0. Взрослая мужская модель.
- Используем уже упакованную геометрию из открытого проекта human-atlas (MIT, код) —
  файлы `public/models/v1/atlas.json` и `body-0..14.bin.gz`, всего ~33 МБ gzip, 2.29 млн треугольников.
  Путь версионирован (`v1`), потому что данные отдаются с годовым кэшем `immutable`; новая
  генерация данных = новая папка `v2`.
  Копируем только данные, не код. Атрибуция BodyParts3D и human-atlas обязательна в приложении
  (страница «Об источниках») и в `ATTRIBUTION.md`.
- Формат чанка: на каждую структуру в манифесте есть `chunk`, `positions` (байтовое смещение,
  float32 × vertexCount × 3), `normals` (int16 нормализованные × vertexCount × 3),
  `indices` (uint32 × indexCount), `bounds`, `system`, `name` (англ.), `conceptId` (FMA).
- Позже пайплайн можно заменить на собственный экспорт из OBJ-архива BodyParts3D в glTF;
  манифест с идентификаторами FJ*/FMA* при этом сохраняется.

## 4. Архитектура

Стек: Next.js (App Router), React, TypeScript, Three.js через react-three-fiber и drei,
Tailwind, zustand для состояния, vitest для юнит-тестов, Playwright для браузерных.
Деплой: Vercel. Пакетный менеджер: pnpm.

Слои и их границы:

```
content/            — исходные данные контента (правит человек)
  structures.csv    — FJ-id, eng name, latin, russian, topic, aliases
  topics.json       — дерево тем курса (1 и 2 курс)
  cards/*.csv       — карточки латынь↔русский по темам (не привязаны к 3D)
scripts/
  build-content.ts  — валидирует content/ и собирает public/content/*.json
public/models/v1/   — atlas.json + body-*.bin.gz (данные BodyParts3D, версионированный путь)
public/content/     — собранные JSON: structures.json, topics.json, cards.json
src/lib/atlas/      — загрузка манифеста и чанков, сборка BufferGeometry, индекс поиска
src/lib/quiz/       — генерация вопросов из structures+topics, проверка ответов
src/lib/srs/        — интервальное повторение (SM-2 упрощённый), чистые функции
src/lib/progress/   — хранение прогресса в localStorage, схема с версией
src/components/atlas/  — сцена, слои, панель структуры, поиск
src/app/            — маршруты: /atlas, /quiz, /cards, /progress, /about
```

Правила:
- `src/lib/*` — чистые функции без React и без DOM (кроме адаптера localStorage), покрываются vitest.
- Контент никогда не редактируется в `public/content` руками; только через `content/` + сборка.
- Один источник правды для идентификаторов структур — `atlas.json` (FJ-id). Всё остальное ссылается на него.

## 5. Модель данных контента

`content/structures.csv` (по одной строке на FJ-структуру, которую мы описываем):

| колонка | пример |
|---|---|
| id | FJ1900 |
| en | Left femur |
| la | Femur sinistrum |
| ru | Левая бедренная кость |
| topic | lower-limb/skeleton |
| aliases | бедро; os femoris |

Сторона (`left/right/—`) не хранится в CSV: она выводится из `en` (`sideFor` в
`src/lib/content/side.ts`, с картой переопределений для ошибок модели, например FJ1469).
`la`/`ru` хранятся без стороны, интерфейс дописывает «(слева)/(справа)».

Парные структуры (левая/правая) объединяются в одно понятие по `la` для карточек и текстовых
вопросов, но в 3D-тестах остаются отдельными. В модели есть дубликаты мешей с одинаковым `la`
(перстневидный хрящ, подъязычная кость, наружный сфинктер и др.) — генератор вопросов обязан
дедуплицировать варианты по `la` и принимать клик по любому мешу с тем же `(la, side)`.

`content/topics.json`: дерево тем курса (39 тем после Плана 2a.2):
- Остеология → Мозговой отдел черепа, Лицевой отдел черепа и подъязычная кость, Зубы, Хрящи гортани
  и носа, Позвоночный столб, Грудная клетка, Кости верхней конечности, Кости нижней конечности.
- Артрология → Связки и мембраны головы и шеи; Связки, мембраны и сухожилия туловища и конечностей.
- Миология → Мышцы головы; шеи и гортани; спины; груди, живота и диафрагма; таза и промежности;
  верхней конечности; нижней конечности.
- Ангиология → Сердце; Артерии головы и шеи; Артерии груди, живота и таза; Артерии конечностей;
  Вены головы, шеи и туловища; Вены конечностей.
- Неврология → Головной и спинной мозг; Черепные нервы и глазница.
- Спланхнология → Дыхательная система; Пищеварительная система; Мочеполовая система;
  Эндокринные и лимфоидные органы.
- Органы чувств и кожа → Орган зрения; Ухо и кожа.
- «Прочее» (`other`): пусто после перевода всех систем; резерв.
Правила: строки ссылаются только на листовые темы; в каждой курсовой теме ≥ 4 различных латинских
терминов (иначе «назови структуру» не соберёт варианты). Темы «мышцы живота» и «связки туловища»
слиты с соседями именно по этой причине: в BodyParts3D нет мышц передней брюшной стенки.

`content/cards/*.csv`: `la, ru, topic, note`. Карточки могут существовать без 3D-структуры
(например, термины отверстий и борозд, которых нет как отдельных мешей).

Собранный `public/content/structures.json` объединяет всё: для каждой FJ-структуры — `en`, `la`, `ru`,
`topic`, `translated: true/false`. Для непереведённых систем `la`/`ru` пустые, `translated: false`.

## 6. Экраны и поведение

### 6.1 Атлас (`/atlas`)
- Сцена с полной моделью, орбитальная камера, свет. На загрузке — прогресс-бар по чанкам.
- Панель слоёв: чекбоксы по системам (кости, суставы/связки, мышцы, артерии, вены, нервы,
  органы, прочее). По умолчанию для 1 курса включены кости и мышцы.
- Клик по структуре: подсветка, карточка справа/снизу: `la` крупно, `ru`, `en`, тема,
  кнопки «Изолировать», «Скрыть», «Учить карточки темы». Пустой клик снимает выделение.
- Поиск: одно поле, ищет по `la`, `ru`, `en`, `aliases`; выбор результата центрирует камеру
  на структуре и выделяет её.
- Кнопка «Сброс» возвращает видимость и камеру.
- Мобильная раскладка: панели превращаются в выдвижные шторки, управление — жесты.

### 6.2 3D-тесты (`/quiz`)
- Выбор темы из дерева, затем режима:
  - «Найди структуру»: показывается `la` + `ru`, нужно кликнуть структуру на модели.
    Видны только структуры темы плюс контекст (например, для мышц плеча — кости). Три попытки,
    после третьей — показать правильный ответ.
  - «Назови структуру»: одна структура подсвечена и камера подведена к ней, четыре варианта
    названий (`la` с `ru` под ним), дистракторы из той же темы.
- Клик по структуре контекста (не из темы) и повторный клик по уже отклонённой части
  попытку не тратят; экран результата держит тему изолированной в атласе, чтобы разбор
  ошибок не показывал лишнее.
- Сессия 10 вопросов, в конце — результат и список ошибок с переходом в атлас.
- Результаты пишутся в прогресс.

### 6.3 Карточки (`/cards`)
- Выбор темы; карточка: лицевая `la`, оборот `ru` (переключатель направления, выбор запоминается
  в `anatomia.cards.direction`).
- Оценка «не помню / помню / легко» → SM-2 упрощённый: «помню» даёт 1 день, потом 3, дальше
  `round(интервал × ease)` при ease 1.3…2.5 (старт 2.5 — то есть 1, 3, 8, 20, 50 дней);
  «легко» умножает тот же интервал на 1.3 и поднимает ease, но у карточки без повторений даёт
  сразу 4 дня (иначе совпало бы с «помню»), «не помню» сбрасывает интервал в 1 день.
- Очередь дня: сначала просроченные, потом новые (лимит новых 20/день, настраивается). Лимит —
  норма на календарный день, а не на сессию: израсходованное считается как сумма `fresh` по
  сегодняшним сводкам `reviews`, поэтому ни повторный вход, ни кнопка «Ещё» новых карточек
  сверх нормы не дают.
- Если на сегодня ничего не осталось, экран показывает ближайшую дату повторения по колоде темы,
  а не только неактивную кнопку.

### 6.4 Прогресс (`/progress`)
- По каждой теме: доля структур, которые студент правильно назвал хотя бы дважды в тестах;
  доля карточек с интервалом ≥ 7 дней.
- Серия дней с активностью. Кнопка «Экспорт/импорт прогресса» (JSON) — страховка от очистки браузера.

### 6.5 Об источниках (`/about`)
- Атрибуция BodyParts3D (CC BY 4.0) и human-atlas, отказ от клинического использования.

## 7. Поток данных

1. Сборка: `scripts/build-content.ts` читает `content/*`, проверяет против `public/models/v1/atlas.json`,
   пишет `public/content/*.json`. Падает при ошибках (см. §9).
2. Рантайм: приложение грузит `atlas.json` + `structures.json`, затем чанки параллельно
   (gzip отдаёт CDN). Из каждой структуры строится `BufferGeometry` в одном `Mesh` на систему
   для скорости; выделение по `instanceId`/атрибуту структуры через raycast.
3. Состояние сцены (видимость систем, выделение, изоляция) — zustand-store, доступный тестам и атласу.
4. Прогресс: `progress/store.ts` читает и пишет `localStorage['anatomia.progress.v1']`,
   с миграцией по версии.

## 8. Обработка ошибок

- Не загрузился чанк: повтор до 3 раз, затем сообщение «Не удалось загрузить модель. Проверьте
  соединение» с кнопкой повторить. Загрузка «всё или ничего»: чанки не совпадают с системами,
  поэтому частичный показ не имеет смысла (решение принято при реализации Плана 1).
- Нет WebGL2: экран с объяснением и ссылкой на список поддерживаемых браузеров;
  карточки и прогресс при этом работают.
- Повреждённый localStorage: сбрасывается в пустой прогресс с предупреждением, старый
  сохраняется под ключом `*.backup`.
- Вопрос ссылается на структуру, которой нет в атласе — невозможно по построению: сборка контента падает.

## 9. Тестирование

- vitest, `scripts/build-content.test.ts`: каждая строка `structures.csv` ссылается на существующий
  FJ-id; у каждой структуры тем остеологии/артрологии/миологии заполнены `la` и `ru`; нет дублей;
  каждая тема из `topics.json` содержит ≥ 4 структур (иначе «назови структуру» не соберёт варианты).
- vitest, `src/lib/quiz`: генерация вопросов даёт уникальные дистракторы из той же темы; проверка ответа.
- vitest, `src/lib/srs`: интервалы и порядок очереди.
- vitest, `src/lib/atlas`: парсер чанка на синтетическом буфере.
- Playwright: страница `/atlas` загружает модель (ждём `data-atlas-ready`), клик по центру
  выделяет структуру и показывает её `la`; `/quiz` проходит один вопрос.

## 10. Порядок работ (крупно)

1. Каркас Next.js + Tailwind + R3F, копирование моделей, загрузчик чанков, сцена с полной моделью.
2. Слои, выделение, панель структуры, поиск (на английских названиях).
3. Контент: `structures.csv` для костей, суставов, мышц; `topics.json`; сборка и валидация.
4. 3D-тесты и прогресс.
5. Карточки и SRS.
6. Мобильная раскладка, страница об источниках, деплой на Vercel, проверка на устройстве жены.
