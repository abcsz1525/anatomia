# Анатомия

3D-атлас и тренажёр по нормальной анатомии для студентов медвузов.

## Разработка

```bash
pnpm install
pnpm dev          # http://localhost:3000
pnpm test         # vitest
pnpm e2e          # playwright
pnpm typecheck
```

## Деплой

Railway: `railway up` из корня проекта (проект должен быть привязан через `railway link`).
Заголовки кэширования для моделей заданы в `next.config.ts`.

## Данные

`public/models/v1` — BodyParts3D 4.0 (CC BY 4.0), см. `public/models/v1/ATTRIBUTION.md`.
Спецификация: `docs/superpowers/specs/2026-09-22-anatomia-mvp-design.md`.

### Кэш геометрии

Чанки геометрии собираются в `BatchedMesh` — по одному на систему; сборка стоит сотни
миллисекунд, поэтому собранные меши лежат в модульном кэше `src/lib/atlas/batch-cache.ts`
(ключ — объект манифеста из кэша данных, `src/hooks/use-atlas-data.ts`).

- **Кэш переживает смену маршрута**: `/atlas → /quiz → /atlas` берёт те же собранные меши
  и не тратит ~0,65 с на пересборку. Кэш живёт в модуле, а не в React, поэтому `BodyMeshes`
  при размонтировании ничего не уничтожает — владелец GPU-ресурсов именно кэш.
- **Сырые буферы чанков освобождаются после первой сборки** (`releaseBuffers`): геометрия
  уже уехала на GPU, а десятки мегабайт `ArrayBuffer` — главный расход памяти на телефоне.
- **Единственная точка очистки — `resetAtlasCache()`**; её вызывает «Повторить» (`retry`)
  на экране ошибки загрузки: данные грузятся заново, а старые меши и материалы
  уничтожаются. Перезагрузка страницы, само собой, сбрасывает и кэш данных, и кэш батчей.
- **Деградировавший бандл** (имена не загрузились, подписи английские) не кэшируется: его
  батчи собираются заново на каждое монтирование и уничтожаются при размонтировании.

## Мобильная версия

Раскладка переключается одним брейкпойнтом Tailwind `md` (768 px) — по ширине окна, без
`navigator.userAgent`: меньше 768 px — мобильная раскладка, 768 px и больше — прежняя
десктопная (её получает и телефон в альбомной ориентации, если он шире 768 px).

- **Слои** — боковой панели нет, её заменяет кнопка «Слои» в правом нижнем углу, которая
  открывает шторку снизу. Правый угол, потому что в dev-режиме левый нижний занимает
  индикатор Next.js. Шторка закрывается крестиком, тапом по фону и клавишей Esc.
- **Карточка структуры** — такая же шторка: выбор структуры (тап по модели, поиск,
  `?focus=`) поднимает её снизу, а не показывает плавающей карточкой справа.
- **Тесты** — панель вопросов стоит под моделью (45 dvh) и сворачивается кнопкой
  «Свернуть» до одной строки: остаются вопрос и «Дальше», модель видна почти целиком.
- **Цели касания** — не меньше 44 px в высоту у основных органов управления:
  галочки слоёв, темы и режимы теста, варианты «назови», «Дальше», «Показать» и
  оценки карточек, кнопки экспорта/импорта на `/progress`. Мелкими остались
  «Прервать» (намеренно), «Сброс» в шторке слоёв, подсказки поиска и кнопки на
  экране результата теста — см. `docs/superpowers/notes/2026-09-23-followups.md`.
- **Жесты уходят в модель**: у канваса `touch-action: none`, поэтому одно касание вращает,
  два — зум и панорама, а страница под пальцем не прокручивается. Выделение отличается от
  вращения порогом сдвига, так что «повернул и отпустил» ничего не выбирает.
- **Шапка** на узком экране прокручивается вбок, а «Об источниках» сокращается до
  «Источники».

Мобильная раскладка закрыта отдельным e2e-проектом: `pnpm e2e --project=mobile`
(390×844, `hasTouch`, `isMobile`; см. `playwright.config.ts` и `e2e/mobile.spec.ts`).

### Проверить на настоящем телефоне

Компьютер и телефон должны быть в одной сети Wi-Fi.

```bash
pnpm dev --hostname 0.0.0.0   # dev-сервер слушает не только localhost
ipconfig getifaddr en0        # macOS: адрес компьютера в сети, например 192.168.1.23
```

На телефоне откройте `http://<ip-компьютера>:3000` — например `http://192.168.1.23:3000`.
Если не открывается: телефон в другой сети (гостевая Wi-Fi или мобильный интернет) либо
фаервол компьютера не пускает входящие соединения на порт 3000.

## Тесты

`/quiz` — сессия из 10 вопросов по одной теме, в двух режимах:

- **«Найди структуру»** — показывается `la` + `ru`, нужно кликнуть структуру на модели.
  На три попытки: после третьей неверной модель сама подсвечивает и показывает правильный
  ответ. Клик по структуре чужой темы (контекст — например, кости под мышцами) не
  засчитывается как попытка, а подсказывает «Это не относится к теме».
- **«Назови структуру»** — структура подсвечена и камера подведена к ней, нужно выбрать
  из четырёх вариантов названий; доступен только темам с ≥4 разными терминами (иначе
  не набрать дистракторов).

Камера при подлёте к структуре (подсказка, показ правильного ответа) подбирает ракурс,
с которого цель действительно видна, а не заслонена другими структурами
(`src/components/atlas/CameraRig.tsx`). Выход из теста («Прервать») возвращает камеру
к общему кадру тела.

В конце сессии — счёт и список ошибок с переходом в атлас (`Показать в атласе`); тема
экрана результатов остаётся изолированной от других тем, пока пользователь не начнёт
новую сессию. Результат сессии один раз пишется в прогресс.

## Прогресс

`/progress` хранит результаты только в `localStorage` браузера, ключ
`anatomia.progress.v1` (см. `src/lib/progress/storage.ts` и `types.ts`).

- **Освоение** по теме — доля терминов (`la`), по которым накоплено ≥2 верных ответа
  суммарно по всем сторонам (`src/lib/progress/stats.ts#topicMastery`).
- **Серия** — число подряд идущих дней с активностью, заканчивающихся сегодня или вчера.
  Дни считаются по местному календарному дню устройства (`src/lib/progress/stats.ts#dayKey`),
  а не по UTC, — сессия поздно вечером не «утекает» на следующий день по UTC-часам.
- **Экспорт/импорт** — кнопки «Экспорт» (скачивает `anatomia-progress.json`) и «Импорт»
  (загружает такой файл обратно); это единственная страховка от очистки браузера,
  так как прогресс нигде не синхронизируется.
- **Очистка** — кнопка «Очистить прогресс» с подтверждением.
- Если сохранённый JSON повреждён или не проходит валидацию схемы, экран не падает:
  прогресс сбрасывается в пустой, а испорченные данные сохраняются под
  `anatomia.progress.v1.backup` на случай ручного восстановления. Пока такая резервная
  копия лежит в браузере, экран показывает уведомление об этом
  (`data-testid="progress-backup-notice"`, `src/lib/progress/storage.ts#hasBackup`).

## Карточки

`/cards` — интервальное повторение терминов одной темы или всего курса. Колода темы: по
одной карточке на каждое различное латинское название (`la`) среди её структур, оборот —
русское название; направление переключается («Латынь → Русский» / «Русский → Латынь»).

- **SM-2, упрощённый** (`src/lib/srs/sm2.ts`). У карточки есть ease 1.3…2.5 (старт 2.5),
  интервал в днях и дата следующего показа `due` (местный календарный день, как и серия):
  - «Не помню» — интервал 1 день, счётчик повторений сбрасывается, ease −0.2;
  - «Помню» — 1 день на первом повторении, 3 на втором, дальше `round(интервал × ease)`;
  - «Легко» — то же, умноженное на 1.3, и ease +0.15; у карточки без повторений (новой или
    сброшенной «Не помню») — сразу 4 дня, иначе «Легко» ничем не отличалось бы от «Помню».

  При ease 2.5 подряд «Помню» дают 1, 3, 8, 20, 50 дней.
- **Очередь дня** (`src/lib/srs/queue.ts`) — сначала карточки с наступившим `due` (по
  возрастанию даты), затем новые, но не больше остатка дневной нормы. Норма задаётся полем
  «Новых в день» (1…100, по умолчанию 20) и хранится не в прогрессе, а отдельным ключом
  `anatomia.cards.newLimit`; остаток нормы считается по сводкам — `newLimit − Σ fresh`
  по `reviews` с сегодняшней датой (`fresh` — сколько новых карточек показала сессия). Это
  норма на календарный день, а не
  на сессию: повторный вход и кнопка «Ещё» новых карточек сверх неё не дают, а строка
  настройки поясняет «(сегодня уже показано K новых)». Вся сессия ограничена 50 карточками.
  Направление («Латынь → Русский» / «Русский → Латынь») запоминается ключом
  `anatomia.cards.direction`.
- **«Не помню» внутри сессии** возвращает карточку в конец очереди, но не больше трёх раз;
  на завтра она в любом случае придёт снова.
- **Когда на сегодня ничего не осталось**, экран настройки вместо неактивной кнопки без
  пояснений показывает «Следующее повторение: 25.09.2026» — ближайшую дату `due` по колоде
  выбранной темы (пустая тема говорит об этом прямо). Тот же расчёт под итогом сессии.
- **Хранение** — в том же `anatomia.progress.v1`, что и тесты: состояния карточек в `cards`,
  сводка каждой сессии в `reviews` (`reviewed`, `again` и `fresh` — сколько карточек сессии
  были новыми). День сессии карточек засчитывается в серию. Испорченные `cards`/`reviews` не
  отменяют результаты тестов: эти поля читаются как пустые, исходная строка уходит в
  `anatomia.progress.v1.backup`, и на `/progress` появляется обычное предупреждение.
- **«Выучено»** на `/progress` — карточки колоды с интервалом ≥ 7 дней
  (`src/lib/progress/stats.ts#cardMastery`); строка «Повторений сегодня» считает сессии
  карточек, законченные сегодня.

## Контент

Все 2234 структуры модели переведены (латынь и русский), 15 систем BodyParts3D,
39 тем в дереве: программа 1 курса (остеология, артрология, миология) и добавленная
программа 2 курса (ангиология, неврология, спланхнология, органы чувств и кожа).
Названия редактируются в `content/structures.csv` (один ряд — одна структура из
`public/models/v1/atlas.json`), затем собираются в `public/content/*.json`, которые
читает атлас в браузере.

Колонки:

| колонка   | значение |
|-----------|----------|
| `id`      | id детали BodyParts3D (`FJxxxx`), должен существовать в манифесте |
| `en`      | английское имя — копия `manifest.parts[].name`, не редактируется вручную |
| `la`      | латинское название (например, `Femur`) |
| `ru`      | русское название (например, `Бедренная кость`) |
| `topic`   | id **листовой** темы из `content/topics.json` (у темы нет дочерних) либо `other` |
| `aliases` | синонимы для поиска, через `;` (например, `os femoris;бедро`) |

Правила:

- `la` и `ru` не должны содержать слов стороны (`left`/`right`,
  `лев(ый/ая/ое/ые)`/`прав(ый/ая/ое/ые)`) — сторона определяется
  автоматически по `en` (см. `src/lib/content/side.ts`) и рендерится
  атласом отдельно как « (слева)»/« (справа)».
- Несколько синонимов в `aliases` разделяются `;`; если синоним содержит
  запятую, всю ячейку `aliases` нужно взять в кавычки по правилам CSV
  (`"синоним, с запятой;другой"`).
- Строки должны быть отсортированы по `id`, `id` не должен дублироваться.
- `topic` — только листовая тема (`skull-facial`, `muscles-thorax`, …) или `other`.
  Темы-контейнеры (`osteology`, `arthrology`, `myology`) строк не принимают:
  такая строка отклоняется как `non-leaf topic myology`.
  Сейчас в `content/topics.json` 39 тем: 7 контейнеров, 31 лист и `other`.
- Каждая непустая листовая тема (кроме `other`) должна содержать ≥4 **разных
  терминов** — считаются уникальные значения `la`, а не строки. Парный орган
  (левый + правый) — это один термин, поэтому двумя парами тему не наполнить.

Команды:

```bash
pnpm build:content --report   # покрытие по всем 15 системам (skeletal … integumentary) без записи файлов
pnpm build:content            # валидирует content/structures.csv и пересобирает public/content/*.json
```

`pnpm build` сам запускает `pnpm build:content` первым шагом, так что
prod-сборка падает, если контент не проходит валидацию. (Скрипт `prebuild`
для этого не годится: pnpm 10 не выполняет pre/post-скрипты без
`enable-pre-post-scripts=true`.)

### SIDE_OVERRIDES — если манифест перепутал сторону

BodyParts3D иногда ошибается в стороне в самом `en`-имени (пример: `FJ1469`
называется "Left flexor pollicis brevis", хотя меш находится справа, а
`FJ1469M` — его зеркало слева). Для таких id не надо подделывать `en` —
вместо этого пропишите id в `SIDE_OVERRIDES` в `src/lib/content/side.ts`,
с комментарием, почему сторона переопределена:

```ts
export const SIDE_OVERRIDES: Record<string, Side> = {
  FJ1469: "right",
  FJ1469M: "left",
};
```

`sideFor(id, en)` живёт в `src/lib/content/side.ts` (рядом с `SIDE_OVERRIDES`)
и вызывается из `scripts/content-rules.ts` при сборке бандла: сначала смотрит в
`SIDE_OVERRIDES` и только потом определяет сторону из `en`.
